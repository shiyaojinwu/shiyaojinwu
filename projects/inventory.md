# 物品管理系统：在持续迭代里打磨后端

[← 返回主页 · 作品存档](../README.md#-作品存档)

**数智工作室主要项目 · 多届成员接力维护 · Java 后端**

物品管理系统是数智工作室的主要项目，由历届成员接力维护、持续迭代，也是我在工作室期间投入较多的项目。我在前人已有的功能和代码基础上，继续参与后端开发、接口联调、问题修复和代码复审。

应用围绕房间、空间和物品组织收纳：通过搜索或扫码找到物品，记录位置与关联关系，也可以邀请其他人共同管理。后续的文件库迭代又带来了分享、查看与编辑权限等场景。

我投入较多的部分包括 **文件搜索与批量分享、接收分享时的数据复制、好友分组相关流程，以及系统通知读取状态的实现**。技术实践主要围绕 Java、Spring Boot、MyBatis-Plus、MySQL、Redis 和消息队列展开。

<details>
<summary><b>我参与的开发：从文件分享，到分组与通知</b></summary>

**文件搜索与分享**

文件库加入之后，我编写了文件搜索接口，处理筛选参数、时间格式与枚举校验，随后实现批量分享及通知调用，并在批量操作失败时标记事务回滚。联调时也修复了参数映射、枚举反序列化等问题。

接收分享时，需要一起处理物品记录、关联图片和文件扩展信息。我实现了这些关联数据的复制，也把文件引用的重建列为后续完善项。这段开发让我更关注一次业务操作涉及的整组数据。

**分组与通知**

好友申请和分组涉及等待、同意、过期等状态。我参与相关代码的复审与合入，也处理临时分组的定时清理、缓存批量扫描和并发更新问题。

系统通知方面，我用 Redis Hash 按用户分片保存读取进度，处理最新通知与未读提示，让通知内容与每个用户的阅读状态分别维护。这个过程需要把消息展示、读取状态和存储方式放在一起看。

</details>

<details>
<summary><b>开发留下的笔记：联调、排障与协作</b></summary>

项目推进中，我陆续记下了 Redis 序列化、跨域请求、消息队列连接、枚举参数绑定，以及异步任务里取不到用户上下文等问题。排查往往需要同时看页面请求、后端处理和实际环境。

例如，接口参数可能在进入业务校验之前，就因为枚举或时间格式不一致而转换失败；切换工作线程后，也不能默认还能读取原线程的登录信息。把失败发生在哪一步弄清楚，才知道该改接口约定、转换逻辑，还是上下文传递。

团队里除了自己写接口，我也参与看代码、讨论方案、合并修改和配合联调。持续迭代让我慢慢养成一个习惯：改完功能后，再看一遍相关数据、缓存与调用方会受到什么影响。

</details>

物品管理系统和心屿一起，构成了我在工作室里很重要的一段开发经历。这里记录我的参与和收获，工作室源码与内部文档不公开。
