# Mindhaven：从心屿延伸出来的尝试

[返回主页作品](../README.md#-作品存档)

心屿是我在数智工作室期间投入较多的项目之一。原版已经基于 **Spring AI 与 DeepSeek** 做了心理知识问答，包含 **RAG 检索与溯源、上下文预算与压缩、固定问答评测与回归**。

**Mindhaven 前后端演示版**延续这些经验，另行构建了一套包含机构账号、问卷、微课堂和聊天的应用。我围绕这些流程提出需求，借助 AI 完成实现与迭代，也在这个过程中继续学习 Web 前端。项目使用 Java、Spring Boot、Spring AI、Vue 3 与 TypeScript，默认用 SQLite 保存数据。

最近的重点是继续完善 **Agent 与 AI 应用**，把页面状态、组件组织和后端行为一起打磨。这个演示版仍在持续开发，仓库暂未公开。

### 心屿里的检索、上下文与评测

- **RAG 与溯源**：结合历史对话消解指代、重写查询，按知识主题与版本过滤检索范围；把相关片段和来源带入生成上下文，让回答能够引用并回查原文。
- **上下文预算与压缩**：完整记录与模型上下文分别管理，预留输出空间后安排历史消息和检索内容；保留近期完整轮次，用摘要版本与覆盖消息序号管理早期内容，避免重复注入。
- **固定问答回归**：覆盖口语、多轮指代、长对话与知识缺失，固定模型、Prompt 和知识版本，对照查询重写与摘要压缩效果；观察 Recall@K、首段耗时和 Token 用量，检查摘要事实及引用支持情况。

这些实践来自原版心屿。另行构建前后端演示时，我也继续处理下面这些业务与工程细节。

### 问卷版本与历史记录

管理员会调整题目和分值，旧答卷却应该保留当时的含义。演示版把草稿和发布版本分开保存，发布时生成快照，填写和提交关联对应版本，答案也保存当时的题目、选项与得分。编辑时检查版本，避免后保存的内容直接覆盖别人的修改。

这样会多存一些数据，但回看旧答卷时不必再猜它对应哪次配置。当前并发处理以单实例为主，多实例下的冲突控制还需要继续完善。问卷计分用于功能演示，不作心理诊断。

### 请求与异步任务中的身份

不同机构的数据需要分开，个人聊天和报告也要各自保存。聊天通过 SSE 返回内容，处理过程会切换到工作线程，因此演示版显式传递机构与用户身份，并在任务结束时清理，避免线程复用后沿用上一个请求的信息。

### 会话记录与模型上下文

完整会话用于回看，每次调用模型的输入则需要控制大小。演示版先预留回复空间，再安排摘要、检索片段和最近几轮完整对话。摘要记录已经覆盖到哪条消息，后续只补入尚未覆盖的内容。

消息区分等待、完成和失败状态。出错的一轮仍保留记录，但不会作为完整对话送给模型。这个演示版本的输入预算目前采用字节估算，还不是精确的 Token 计数。

## AI-agent

旅游 AI 助手是我最早的个人 AI 练手项目，基本借助 AI 实现，架构比较简单。我用旅游问答接触 Spring AI、RAG、多轮消息和工具调用，也尝试了 PGVector 与 MCP 接入，先弄清楚查找资料、调用模型与回填工具结果怎样连起来。

这些入门经验后来在心屿中继续发展，再延续到现在的 Mindhaven。
